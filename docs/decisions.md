# 口径与实现决策

依据：用户提供的两份 V1.2 Word 文档（2026-11-05），实现时以可复现的严格口径解决文档内部冲突。

1. **主指标 exact**：类型、起止位置全部一致才计 TP。Partial 不计 TP，同时计 1 FP 与 1 FN；拆分和合并按每个真实实体/预测分别计数，保持 TP+FP=预测数、TP+FN=金标数。修正文档骨架把 partial 从 FN 中消掉的问题。
2. **诊断匹配**：先冻结所有 exact，余下同类型 IoU≥0.5 使用最大配对数、最大 IoU 分配；嵌套按内层优先稳定排序。边界准确率为 exact/(exact+partial)，不使用恒为 1 的 exact/TP。
3. **双轨报告**：标准文本与复杂文件各自报告，不提供掩盖双轨差异的混合总体 F1。高风险同时报告 micro、macro 与最差类别；门禁检查宏召回及每个有足够样本的类别，缺失类别/不足覆盖阻断正式发布。
4. **非 PII 分母**：使用显式标注、互不重叠的 non_pii_candidates；只有难负样本时以其为受限分母并声明。字符误删率另报。未知分母显示 null，正式门禁不得将其视为 0。
5. **16,000 条唯一数据**：14,000 标准文本+2,000 复杂文件；train/dev/holdout/gate 独立切分，默认 11,200/1,700/1,600/1,500。门禁 1,500 与“5%”无法同时满足，以明确数量为准。holdout 不抽入反复调参的 gate。各 JSONL 是清单的视图，不是新增独立样本。
6. **合成数据声明**：全部为程序构造的虚构样本，不代表真实客户分布、真实模型效果或真实人工质检；不会伪造 86% 改善。扫描件自带可复用 OCR 噪声产物，但必须标明 replay；真实 OCR 需显式配置外部 OCR 引擎。
7. **四元组和输入摘要**：数据、模型、规则、代码版本、配置指纹、文件内容摘要共同确定缓存与可比性。缓存/断点续跑不掩盖错误，不把缓存读取时间作为推理时延。
8. **门禁证据**：缺指标、NaN、样本执行失败、未覆盖 gate、增量评测均不能给出正式 PASS。L1 对软阈值保留诊断并保守阻断，L2 输出三级结果，L3 还需真实人工/合规签字。阈值属于待业务确认的示例配置，所有修改需要独立审核记录。
9. **集成边界**：本地 JSONL 是可审计离线镜像；连接 Langfuse 时同步到版本化 Dataset 并关联 Dataset Run。PostgreSQL 存运营记录、ClickHouse 存分析结果；开发测试使用项目内 SQLite 适配层，不在用户电脑部署数据库。集成需显式启用，密钥只从环境读取。
10. **文件处理**：TXT/DOCX/原生 PDF 支持实际解析和导出；扫描/跨页版式通过块级映射和 OCR 适配器处理。替换长度保持，重叠实体按区间并集覆盖。PDF 区域删除使用真实 redaction；复杂格式保真单独报告，不能由“能打开”推断版式无损。
